# DealerOS 開発プレビュー オペレーターテストチェックリスト（E10.2）

> 目的: Developer Preview（開発プレビュー環境）で、主要な業務フローが実機・実データで正しく動作することをオペレーターが確認するためのチェックリストです。
>
> 使い方: 各項目の「手順」を上から順に実施し、「期待結果」と一致するか確認してください。一致しない場合は「失敗メモ」欄に事象・端末・時刻・スクリーンショット名を記録してください。
>
> 環境前提: 開発（Development）環境でのみ実施。本番環境では実施しないこと。OCRを検証する場合は `OPENAI_API_KEY` が設定され、モデルは `gpt-4.1-mini`（未対応アカウントでは `OCR_MODEL=gpt-4o-mini`）であること。
>
> 優先度: **高** = プレビュー合格に必須 / **中** = 重要だが代替可 / **低** = 余力があれば確認

---

## 1. ログイン
- **テスト目的**: 認証とディーラー・スコープ（自店舗データのみ表示）が機能することを確認する。
- **手順**:
  1. `/login` を開く。
  2. 発行済みのテストアカウントでメールアドレス・パスワードを入力しログイン。
  3. ダッシュボード（または初期画面）が表示されることを確認。
  4. 顧客・見積など各一覧に、自店舗のデータのみが表示されることを確認。
- **期待結果**: ログイン成功。他店舗のデータが一切表示されない。未ログイン状態で保護ページを開くと `/login` にリダイレクトされる。
- **失敗メモ**:
- **優先度**: 高

## 2. 顧客作成
- **テスト目的**: 新規顧客の登録と保存、一覧・詳細への反映を確認する。
- **手順**:
  1. 顧客管理を開き「新規顧客登録」を押す。
  2. 姓（必須）、名、フリガナ、電話番号、住所などを入力。
  3. 保存する。
  4. 一覧に表示された顧客を開き、入力値が正しく表示されることを確認。
- **期待結果**: 顧客が作成され、一覧・詳細に正しく表示される。姓未入力時はエラーメッセージが表示され保存されない。
- **失敗メモ**:
- **優先度**: 高

## 3. 車両作成
- **テスト目的**: 顧客に紐づく車両の登録を確認する。
- **手順**:
  1. 対象顧客の詳細、または車両登録画面を開く。
  2. メーカー・車種・ナンバー・車台番号（VIN）などを入力し保存。
  3. 顧客詳細の「紐付き車両」に表示されることを確認。
- **期待結果**: 車両が作成され、正しい顧客に紐づく。一覧・詳細に反映される。
- **失敗メモ**:
- **優先度**: 高

## 4. 車検証OCR（カメラ / 画像 / PDF）
- **テスト目的**: カメラ撮影・画像アップロード・PDFアップロードからAI抽出までが動作することを確認する。
- **手順**:
  1. 見積管理 →「顧客・車両登録」を開く（またはOCRアップロード画面）。
  2. **(a) 画像**: 実物の車検証画像をアップロード。
  3. **(b) PDF**: 車検証PDFをアップロード。
  4. **(c) カメラ**（モバイル）: カメラで車検証を撮影。
  5. 解析完了まで待つ（ローディング表示を確認）。
- **期待結果**: いずれの入力でも抽出が完了し、抽出項目（氏名・住所・車名・型式・初度登録・車台番号・登録番号・車検満了日・所有者・使用者）がレビュー画面に表示される。フリガナは車検証に記載がある場合のみ表示（空欄可）。
- **失敗メモ**:
- **優先度**: 高

## 5. OCRレビューと修正
- **テスト目的**: 抽出結果を保存前にオペレーターが確認・修正できることを確認する。
- **手順**:
  1. OCR完了後のレビュー画面を開く。
  2. 誤読された項目を手動で修正する。
  3. 反映する項目のチェックを切り替える。
- **期待結果**: 各項目が編集可能で、修正内容が確定内容に反映される。誤った値が自動確定されない。
- **失敗メモ**:
- **優先度**: 高

## 6. OCR → 見積ハンドオフ
- **テスト目的**: OCR確定後、登録した顧客・車両がプリセットされた状態で見積ウィザードが開くことを確認する。
- **手順**:
  1. レビュー確定後、重複チェック（同名・同電話の顧客／同一VIN・ナンバーの車両）の表示を確認。
  2. 「新規登録」または「既存を使用」を選択して保存。
  3. 見積作成画面が開くことを確認。
  4. **(a) 新規顧客+新規車両**の場合、顧客・車両が自動選択されていることを確認。
  5. **(b) 既存を採用**した場合も、正しい顧客・車両が選択されていることを確認。
- **期待結果**: 見積ウィザードで顧客・車両が正しくプリセットされる。オペレーターが操作するまで見積は自動作成されない。既存データが自動上書きされない。
- **失敗メモ**:
- **優先度**: 高

## 7. 見積作成
- **テスト目的**: カテゴリ別ウィザードと料金計算が正しく動作することを確認する。
- **手順**:
  1. カテゴリを選択（コーティング / PPF / ウィンドウ / メンテナンス / 洗車 / ルームクリーニング / その他、複数可）。
  2. ボディサイズ・商品・オプションなど、選択カテゴリに応じたステップのみが表示されることを確認。
  3. 業者顧客の場合、業販掛け率が自動適用されることを確認。
  4. 小計・値引き・消費税・合計を確認し、保存する。
- **期待結果**: 必要なステップのみ表示。プレビュー合計と保存後の合計が一致。業者割引・手動調整・税計算が正しい。
- **失敗メモ**:
- **優先度**: 高

## 8. 見積PDF
- **テスト目的**: 見積PDFのブランディング・明細順・金額表示を確認する。
- **手順**:
  1. 作成した見積の「PDF表示」を開く。
  2. 店舗名・ロゴ・住所・登録番号・フッター（ブランディング）を確認。
  3. 明細のカテゴリ順（コーティング→PPF→ウィンドウ→メンテナンス→洗車→ルームクリーニング→その他）を確認。
  4. 合計金額が見積と一致することを確認。
- **期待結果**: ブランディングが反映され、明細順・金額が正しい。設定があればQR/LINE QRが表示される。
- **失敗メモ**:
- **優先度**: 高

## 9. 予約作成（カレンダー）
- **テスト目的**: カレンダーからの予約作成と表示を確認する。
- **手順**:
  1. カレンダーを開く。
  2. 空きスロットをタップして予約を作成（顧客・車両・作業内容・時間）。
  3. 作成した予約がカレンダー上の正しい日時に表示されることを確認。
  4. 予約を開いて内容を確認。
- **期待結果**: 予約が正しい日時（JST）で作成・表示される。営業時間・キャパシティの警告が想定通り表示される。
- **失敗メモ**:
- **優先度**: 高

## 10. 作業指示（Work Order）
- **テスト目的**: 見積からの作業指示作成と進捗管理を確認する。
- **手順**:
  1. 承認済み見積から「施工指示作成」を実行。
  2. 作業指示が作成され、顧客・車両・明細が引き継がれることを確認。
  3. ステータス（予定 / 進行中 / 完了 など）を変更。
- **期待結果**: 作業指示が正しく作成され、見積内容が引き継がれる。ステータス更新が反映される。
- **失敗メモ**:
- **優先度**: 中

## 11. 作業完了報告書（Completion Report）
- **テスト目的**: 完了報告書の作成とPDFを確認する。
- **手順**:
  1. 作業指示から完了報告書を作成。
  2. 作業内容・写真など必要項目を入力。
  3. 完了報告書PDFを表示し、ブランディング・明細を確認。
- **期待結果**: 完了報告書が作成され、PDFに店舗ブランディングと作業内容が正しく表示される。
- **失敗メモ**:
- **優先度**: 中

## 12. 請求書（Invoice）
- **テスト目的**: 見積/作業指示からの請求書作成、支払期限・金額・支払進捗を確認する。
- **手順**:
  1. 承認済み見積または作業指示から「請求書作成」を実行。
  2. 明細・小計・税・合計が引き継がれることを確認。
  3. 締め請求設定がある店舗では、支払期限（due_date）が締め日・支払日から算出されることを確認（都度請求では空でも可）。
  4. 入金を登録し、入金済み・残高・入金進捗（％）・ステータスが更新されることを確認。
  5. 請求書PDFを表示し、ブランディング・明細順・金額を確認。
- **期待結果**: 請求書が正しく作成される。金額が見積と一致。入金登録で残高・進捗・ステータスが更新される。PDFのブランディング・明細順・金額が正しい。
- **失敗メモ**:
- **優先度**: 高

## 13. 統合請求プレビュー（Statement Preview）
- **テスト目的**: 締め請求（業者）顧客の統合請求プレビューが正しく集計されることを確認する。
- **手順**:
  1. 店舗設定に締め日・支払日を設定（例: 20日締め / 翌月15日払い）。
  2. 業者顧客（是ビジネス）の詳細を開く。
  3. 「統合請求プレビュー」に請求期間・件数・小計・消費税・合計・支払期限が表示されることを確認。
  4. 明細行（発行日・車両・登録番号・区分・請求番号・金額）を確認。
  5. 対象請求がない期間では空状態が表示されることを確認。
- **期待結果**: 締め請求顧客のみプレビューが表示される。都度請求顧客には表示されない。集計値が期間内請求書の合計と一致する。欠損値は安全に表示される。
- **失敗メモ**:
- **優先度**: 中

## 14. 統合請求書PDF（Statement PDF）
- **テスト目的**: 統合請求書PDFがオンデマンド生成され、ブランディング・集計が正しいことを確認する。
- **手順**:
  1. 統合請求プレビューの「統合請求書PDF」を押す。
  2. PDFが新規タブで表示されることを確認。
  3. 顧客名・請求期間・締め日・支払期限・明細行・件数・小計・税・合計を確認。
  4. 店舗ブランディング（ロゴ・名称・フッター）を確認。
- **期待結果**: PDFが生成され、集計・期間・ブランディングが正しい。都度請求顧客ではPDFが生成されない（エラーメッセージ）。データは保存されない（レコード非永続）。
- **失敗メモ**:
- **優先度**: 中
