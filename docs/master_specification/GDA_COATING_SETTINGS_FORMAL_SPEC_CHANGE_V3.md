## 1. 目的

コーティング設定を、既存DealerOSの施工ルール・店舗ランク・過去データとの互換性を維持しながら、店舗が車両サイズ別価格を直接設定できる方式へ変更する。

本変更は、単なる画面デザイン変更ではない。価格データ契約、見積計算、旧データ移行表示、入力検証を同一の正式仕様として定義する。

## 2. 今回のオーナー確定事項

1. 車両サイズは7段階とする。
2. 各サイズの価格は税抜価格を直接入力する。
3. Mサイズ基準価格とサイズ倍率による新規価格設定を廃止する。
4. 2層目・3層目は、単なる割合・固定額加算ではなく、実際に施工する追加レイヤー商品を選択する現行DealerOS方式を維持する。
5. 2層目・3層目の商品選択は、店舗ランクとGYEON施工組み合わせ規則に従う。
6. 2層目と3層目は使用する液剤が異なるため、商品選択と7サイズ別価格を層ごとに完全分離する。
7. `XXL`は`XL`へ統合せず、車両サイズ仕様から廃止する。

## 3. 正式な車両サイズ

次の7サイズを正本とする。

1. `SS`
2. `S`
3. `M`
4. `ML`
5. `L`
6. `LL`
7. `XL`

`XXL`は正式な車両サイズではなく廃止する。`XL`の別名、上位互換、価格フォールバックとしても使用しない。新UIのボタン、価格入力列、型定義、価格カタログ、3M自動選択結果および新規保存値から除外する。

既存保存データに`XXL`が存在する可能性があるため、実装前に読み取り専用で件数と利用箇所を確認する。存在した場合も`XL`へ自動統合・自動変換しない。対象レコードは旧不正値として明示し、権限を持つ担当者が7サイズから正しい値を手動再選択するまで、新しい見積計算への利用をfail closedで停止する。

過去に確定済みの見積書、請求書、施工記録などの履歴表示に文字列`XXL`が保存されている場合、その履歴スナップショットは改ざん・再計算しない。ただし新規作成、複製、再見積では`XXL`を引き継がず、7サイズの再選択を要求する。

### 3.1 車両サイズの3M算定フロー

正式フローは次のとおりとする。

```text
車検証OCR
  ↓
長さ・幅・高さをフォームへ反映
  ↓
3M値を算出
  ↓
SS / S / M / ML / L / LL / XL の7分類から推奨サイズを自動選択
  ↓
該当ボタンの色を変更して選択状態を表示
  ↓
店舗担当者が必要に応じて手動修正
  ↓
担当者が最終確定したサイズを保存
```

- 3M値は`長さm + 幅m + 高さm`で算出する。
- OCR値をフォームに反映し、フォーム値を算定入力の正本とする。
- 3項目のいずれかが欠落または不正な場合、推測値を自動確定せず手動選択を要求する。
- 自動選択は初期値であり、担当者による修正を常に許可する。
- 保存正本は自動推定値ではなく、担当者が最終確定した7分類の値とする。
- 3M値が最大境界以上の場合も、返却可能な最大分類は`XL`とする。`XXL`を生成しない。
- 7分類の境界値は既存の正式な分類表を参照する。GenSparkまたはClaudeが独自に境界値を変更・推測してはならない。

## 4. 価格の正本

### 4.1 共通規則

- 価格は日本円の税抜整数で保存する。
- 税込価格を正本として保存しない。
- 小数、負数、文字列、無限値は保存不可とする。
- 入力画面には「円・税抜」を明示する。
- 表示時は3桁カンマ区切りとする。
- 保存時はカンマを除いた整数とする。

### 4.2 1層目価格

各ベースコーティング商品は、7サイズそれぞれの基本価格を直接保持する。

概念データ形:

```ts
type BodySizeKey = "SS" | "S" | "M" | "ML" | "L" | "LL" | "XL";

type SizePriceMap = Record<BodySizeKey, number | null>;

interface CoatingBaseProductPrice {
  productId: string;
  pricesBySize: SizePriceMap;
}
```

### 4.3 2層目・3層目の追加レイヤー価格

2層目・3層目は「35%加算」「20,000円加算」のような匿名の加算設定ではない。

実際に施工する追加レイヤー商品を選択し、その商品の対象サイズ価格を加算する。

各追加レイヤー商品は、2層目用と3層目用に分離された7サイズ税抜追加価格を直接保持する。

概念データ形:

```ts
interface CoatingLayer2ProductPrice {
  productId: string;
  layer2PricesBySize: SizePriceMap;
}

interface CoatingLayer3ProductPrice {
  productId: string;
  layer3PricesBySize: SizePriceMap;
}
```

2層目用と3層目用の価格契約を共有してはならない。同一の商品識別子が両方の層で利用可能な場合でも、`layer2PricesBySize`と`layer3PricesBySize`は別の保存・検証・読込対象とする。一方の価格を他方へ自動複製、代用、フォールバックしてはならない。

## 5. 見積計算

選択サイズを`size`とした場合、税抜価格は次の式で計算する。

```text
1層施工 = baseProduct.pricesBySize[size]

2層施工 = baseProduct.pricesBySize[size]
          + layer2Product.layer2PricesBySize[size]

3層施工 = baseProduct.pricesBySize[size]
          + layer2Product.layer2PricesBySize[size]
          + layer3Product.layer3PricesBySize[size]
```

次の方式は禁止する。

- Mサイズ価格へのサイズ倍率適用
- 2層目・3層目の一律パーセント加算
- 商品識別子を持たない固定額加算
- 選択された追加レイヤー商品の代わりに別商品価格を代用する処理
- 2層目価格を3層目価格へ、または3層目価格を2層目価格へ代用する処理
- 未設定価格を0円として計算する処理

## 6. 商品選択と施工組み合わせ制御

現行DealerOSの制御を維持する。

- 1層目は店舗ランクで利用可能なベース商品だけを表示する。
- 2層目は、選択中の1層目に対して施工可能な商品だけを表示する。
- 3層目は、2層目が選択されている場合だけ選択可能とする。
- 3層目も1層目との正式な組み合わせ規則を通過しなければならない。
- Certified限定商品はCertified店舗だけに許可する。
- 店舗ランク不明、商品不明、不正な組み合わせ、価格未設定はfail closedとし、部分的な価格で見積を作成しない。
- 見積明細には、1層目・2層目・3層目の商品識別子、商品名、層の役割を保持する。

GYEON施工組み合わせ規則は店舗ユーザーが自由編集する価格設定ではない。既存の正式マトリクスを正本として使用する。

## 7. コーティング設定UI

### 7.1 商品切替方式

承認済みのプッシュボタン方式を維持する。

- ドロップダウンは禁止する。
- 取扱可能なコーティング剤をプッシュボタンで表示する。
- 選択中の商品は`aria-pressed="true"`とする。
- 選択中の商品1件の設定だけをメイン領域へ表示する。
- 全商品を1枚の巨大な縦長テーブルへ並べない。

### 7.2 ベース価格セクション

選択中のベース商品について、7サイズの1層目税抜価格を入力できること。

### 7.3 追加レイヤー価格セクション

「2層目 加算率」「2層目 加算額」「3層目 加算率」「3層目 加算額」は削除する。

代わりに「2層目価格設定」と「3層目価格設定」を別パネルとして設ける。

- 各パネルで、その層に利用可能な液剤を別々のプッシュボタンで切り替える。
- 各パネルで、選択中の液剤について7サイズの追加価格を直接入力する。
- 2層目の商品選択、入力値、未設定、無料、エラー、旧価格確認、保存結果は3層目から独立させる。
- 3層目の商品選択、入力値、未設定、無料、エラー、旧価格確認、保存結果は2層目から独立させる。
- その商品が2層目・3層目のどこで使用可能かを、正式マトリクスから導出した説明として表示する。
- Certified限定の場合は明示する。
- 組み合わせ規則そのものはこの画面で編集させない。

説明表示は固定文言ではなく、既存の正式なコーティング組み合わせマトリクスおよび店舗ランクから導出する。UIへ規則を二重にハードコードしてはならない。

表示内容には最低限、次を含める。

- 現在の店舗ランクで価格設定可能か
- 2層目として使用可能か
- 3層目として使用可能か
- 組み合わせ可能な1層目商品
- 使用不可の場合の理由

GenSparkは表示コンポーネントと状態を設計する。実装時は、既存マトリクスを参照するアプリケーション側アダプターが次のような表示用データを生成してUIへ渡す。

```ts
interface UpperLayerAvailabilityView {
  productId: string;
  productLabel: string;
  allowedForShopRank: boolean;
  allowedPositions: Array<"layer2" | "layer3">;
  compatibleBaseProductIds: string[];
  unavailableReason: string | null;
}
```

上記はUI受け渡しの概念形であり、GenSparkが独自の組み合わせJSONを正本として作成することを意味しない。

### 7.3.1 追加レイヤー価格入力と組み合わせ可否の関係

追加レイヤー価格は「層位置 × 追加レイヤー商品 × 車両サイズ」で一意であり、現在選択中のベース商品には依存しない。

したがって、価格設定画面では次の規則を適用する。

- 現在の店舗ランクで使用可能な追加レイヤー商品は、特定のベース商品と組み合わせ不可の場合があっても価格入力を許可する。
- 各商品には、組み合わせ可能なベース商品と使用可能な層位置を読み取り専用で表示する。
- 特定ベース商品との組み合わせ不可は、価格データを削除・無効化する理由にはしない。
- 実際の組み合わせ制限は見積ウィザード側で正式マトリクスに従って適用する。
- 現在の店舗ランクで全面的に使用不可の商品はロック表示とし、価格入力領域を表示しない。
- 正式マトリクス上、どのベース商品・どの層位置でも使用できない商品もロック表示とし、価格入力領域を表示しない。
- ロック状態の商品を非表示にして理由を隠さず、商品名、ロック状態、利用不可理由を表示する。

### 7.4 想定施工時間

既存の1層、2層、3層の想定施工時間設定を維持する。

施工時間は価格とは別の0以上の整数（分）として扱う。

### 7.5 付帯セクション

次のセクションは維持する。

- コーティングオプション施工
- 部分PPF施工（付帯用）

各行は、名称、税抜金額、所要時間、削除操作を持つ。行追加機能を維持する。

部分PPF施工（付帯用）は、独立したPPF設定画面の単体施工価格とは別管理とする。

### 7.6 保存操作

- 保存ボタンは`position: static`とする。
- `sticky`および`fixed`は禁止する。
- フォーム最下部に通常配置する。
- 下部コンテンツへ重ねない。
- 保存中、保存成功、保存失敗を明示する。
- 画面を開いただけでは保存しない。

## 8. 0円と未設定

`0円`と`未設定`は別状態として扱う。

### 未設定

- データ値は`null`相当とする。
- 該当する商品とサイズの組み合わせは見積ウィザードで選択不可とする。
- 0円へ自動変換しない。
- 商品ボタンおよび入力欄に「未設定」または「要確認」を表示する。

### 0円

- 意図的な無料提供だけを表す。
- 単に数値欄へ`0`を入力しただけでは確定させない。
- 「無料に設定」操作または明示確認を必要とする。
- 確定後は「無料」と表示する。

## 9. 旧データからの移行表示

旧形式は次の値を使用している。

- `base_price_m`
- `size_multipliers`
- `topcoat_prices`

新形式が未保存の場合だけ、旧値から7サイズの候補値を生成して初期表示する。

```text
旧1層目候補価格 = round(base_price_m × size_multiplier[size])

旧共有トップコート参考価格 = round(topcoat_price × size_multiplier[size])
```

移行時の必須規則:

- 1円単位で四捨五入する。
- 旧`topcoat_prices`は層位置を識別しない共有値であるため、2層目・3層目の両方へ自動複製しない。
- 既存の保存値・正式マトリクス・利用実績から層位置を一意に確定できない場合は、参考値として表示し、各層で担当者の確認と明示保存を要求する。
- 初期表示だけでは新形式を保存しない。
- 画面上部に「旧価格設定から7サイズ別価格へ変換しました」と表示する。
- 未確認の商品ボタンに「要確認」を表示する。
- ユーザーが内容を確認して保存に成功した後だけ、変換通知を消す。
- 保存失敗時は変換通知を維持する。
- 旧データは新形式の読込・運用が安定するまで読み取り互換のため保持する。
- 過去に確定済みの見積明細金額は再計算しない。

## 11. 入力・表示状態

2. 未設定
3. 意図的な無料
4. 入力エラー

## 12. 金額入力仕様

- 入力には`inputmode="numeric"`を使用する。
- フォーカス中は数字入力を妨げない。
- フォーカスを外した時に3桁カンマ区切りへ整形する。
- 全角数字は安全に半角変換するか、明確なエラーを表示する。
- マイナス、小数、指数表記、空白だけの値を拒否する。
- 保存前にすべての変更対象を再検証する。
