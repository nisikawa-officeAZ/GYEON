## 2. 目的と非目的

### 2.1 目的

- GYEON取扱店がPC、タブレット、スマートフォンから商品を正確に発注する。
- 商品、価格、在庫、バックオーダー、配送、決済、請求、追跡を一つの業務フローで扱う。
- スタッフが下書きを作成し、オーナーが最終発注する。
- 倉庫は見落としにくい作業キューで受注し、発送まで追跡する。

- 取扱店側の店舗在庫管理

### 3.1 最終発注

- スタッフは最終発注できない。
- スタッフの操作は「オーナー確認を依頼」で止まる。
- オーナーが内容を確認して初めて正式発注となる。
- オーナー不在を理由にスタッフへ最終発注権限を暗黙付与しない。

- 保存済みカートに対する送料ルール変更時の再計算タイミングは未確定。

## 8. 支払方法

通常取扱店には次の3方式を表示する。

1. カード決済
2. 銀行振込・前払い
3. 代金引換

掛け売り設定された取扱店には支払方法の選択UIを表示しない。読み取り専用で「掛け売り・月末締め・支払期限」を表示する。

### 8.1 カード決済

- 採用カードPSPはStripeとし、接続対象はStripe PaymentsのPaymentIntents APIを正式候補とする。
- Stripe口座は取得済みである。ただし口座ID、APIキー、Webhook secretその他の秘密情報は本仕様書へ記録しない。
- オーナーの最終発注時に、バックオーダー商品を含む注文の税込支払総額を1回で売上確定する。与信だけを保持して発送ごとに売上確定する方式、マルチキャプチャー、発送ごとの追加PaymentIntentは採用しない。
- 「在庫商品を先に発送」と「すべて揃ってからまとめて発送」は物流方針だけを表し、決済額・決済回数を変えない。JCBを含むカードブランドで同じ全額先払い契約を用いる。
- 正確なStripe API version、利用可能なカードブランド、即時売上確定、取消、部分／全額返金、Webhook署名・再送・最終性・照合方法は別実装ゲートで固定し、実アカウントとsandboxで検証する。採用フローはIC+料金体系およびマルチキャプチャー機能を前提にしない。
- 営業日の当日締切時刻までに、オーナーの最終発注とカード全額決済が完了した在庫商品は、原則として当日発送する。
- 倉庫営業カレンダーの初期締切は15:00。日別設定がある場合は日別設定を優先する。
- 当日発送は当日到着を意味しない。
- 倉庫休業日、締切後、在庫切れ、バックオーダー、承認遅延、住所確認、配送障害は翌営業日以降となる。
- カード決済前は商品追加、削除、数量、配送先、コメントを変更でき、最終発注時にサーバーが全額を再計算する。
- カード全額決済後は商品追加、削除、数量変更その他の金額変更を禁止する。変更のために保存カードへ自動追加請求せず、新しいPaymentIntentも自動作成しない。
- 注文取消、発送不能または確定欠品の場合だけ、サーバーが正本注文と未履行額から算定した金額を部分返金または全額返金する。返金成功を注文取消・減額の前提証跡とし、失敗または応答不明時は元の決済済み注文を維持して手動確認へ送る。
- 画面には「バックオーダー商品を含む注文は注文確定時に全額決済し、未入荷商品は入荷後に追加送料なしで発送し、発送不能またはキャンセルとなった商品は返金する」旨を最終決済前に表示する。

### 8.2 銀行振込・前払い

- 発送は入金確認後。
- PayPay銀行の入金通知API接続を利用し、サーバー側でリアルタイム入金確認を行う将来契約とする。
- 入金通知を受けただけで注文を自動確定しない。銀行取引ID、対象注文、請求金額、重複利用を照合する。
- 不足、過入金、重複、名義相違、対象不明は「入金確認保留」とし、倉庫へ発送可能通知を出さない。
- 振込名義が注文者と異なる場合は確認が遅れる旨を表示する。
- 振込手数料は取扱店負担とする。
- PayPay銀行APIの実際の認証・通知・再送仕様は、公式契約確認後の別実装フェーズで確定する。

### 8.3 代金引換

- 営業日の当日締切時刻までにオーナーの最終発注が完了した在庫商品は、原則として当日発送する。
- 顧客直送では代金引換を選択できない。
- バックオーダーを含む注文で在庫商品を先に発送する場合、バックオーダー分を含む注文全額を最初の代引発送で回収する。
- 後日のバックオーダー発送では代引による再請求を行わない。
- 代引手数料の有無・金額は未確定。GenSparkは固定金額を作らない。

## 9. 掛け売り

### 9.1 設定

掛け売りはスーパーアドミンだけが店舗単位で設定する。

- 掛け売り有効／停止
- 月末締め（固定）
- 支払サイト（翌月／翌々月等）
- 支払日（取引先の支払条件に合わせて個別設定）
- 適用開始日
- 設定者、設定日時、変更履歴

掛け売り上限、支払遅延時の自動停止、管理者解除条件は未確定。未確定値をUIへ固定しない。

### 9.2 発注・発送

- 掛け売り店舗にはカード・振込・代引の選択欄を出さない。
- オーナーが最終発注した時点で、事前決済を待たず倉庫作業キューへ送る。
- 画面には「掛け売り／月末締め／支払期限」を確認表示する。

### 9.3 月末請求

- 実際に発送完了した商品を売掛対象とする。
- 月末に取引先ごとにまとめて請求書PDFを発行する。
- 分割発送が月をまたぐ場合、各月に実際に発送した数量を各月の請求対象とする。
- 支払期限は請求書発行時点の店舗設定をスナップショットし、後日の設定変更で発行済み請求書を書き換えない。
- PayPay銀行の入金通知は個別注文ではなく未払い月次請求書へ照合する。

## 10. 倉庫営業カレンダーと発送可能日

### 10.1 スーパーアドミン設定

スーパーアドミン画面に倉庫営業カレンダーを必須設置する。

- 通常営業
- 休業
- 臨時営業
- 短縮営業
- 日別締切時刻
- 休業理由・備考

土曜日、日曜日、祝日をコードで固定休業日にしない。土曜日発送も日別設定で可能にする。

### 10.2 最短発送可能日の計算起点

| 支払方式 | 計算起点 |
|---|---|
| カード | オーナー最終発注かつ注文全額のカード決済完了 |
| 銀行振込 | 入金照合完了 |
| 代引き | オーナー最終発注 |
| 掛け売り | オーナー最終発注 |

在庫、バックオーダー、当日締切時刻、倉庫営業カレンダーを合わせて最短発送可能日を表示する。「最短発送可能日」と「発送確定日」を同一表示にしない。

### 10.3 変更通知

カレンダー変更により既存注文の発送予定日が変わった場合、対象取扱店へベル通知とメールを自動送信する。

## 11. バックオーダーと発送

- バックオーダー商品を含む注文だけ、注文全体で発送方針を選択させる。
- 選択肢は「在庫商品を先に発送」と「すべて揃ってからまとめて発送」。
- 商品単位で発送方針を選択させない。
- 後日のバックオーダー発送に追加送料を発生させない。
- 取扱店向け出荷の分割発送と、GYEON本社からOffice AZへの入荷分納なしは別契約であり混同しない。
- バックオーダーを注文全体のstatusへ追加せず、配送・在庫の別事実として表示する。

## 12. 注文状態、編集、倉庫受付

注文の集約状態は6つだけとする。

`draft / submitted / approved / fulfilling / fulfilled / cancelled`

- `draft`: カート、編集可。
- `submitted`: オーナー最終発注済み、倉庫受付待ち。カード決済済み注文の商品・数量・金額は編集不可とし、取消は返金ワークフローでのみ行う。
- `approved`: 倉庫受付確定。商取引内容を編集不可。
- `fulfilling`: 引当、ピック、検品、発送、バックオーダー対応中。
- `fulfilled`: 全発送義務完了。
- `cancelled`: 取消済み。

倉庫画面の操作ラベルは「倉庫受付確定」とする。バックオーダー、入荷待ち、発送済み、配送中、納品済みは別軸の事実・バッジとして扱う。

## 13. 倉庫通知・作業キュー

ベル通知だけを倉庫の正本にしない。倉庫画面に消えない「新規受注／出荷待ちタスク」を作成し、ベルは注意喚起として使う。

### 13.1 倉庫へ送る時点

- カード: 注文全額のカード決済成功と証跡保存後
- 銀行振込: 入金照合成功後
- 代引き: オーナー最終発注後
- 掛け売り: オーナー最終発注後

### 13.2 倉庫タスク必須情報

- 注文番号、注文日時、店舗、担当者
- 支払方式と確認状態
- 配送先、配送希望、注意事項
- バックオーダー発送方針
- 最短発送可能日
- 未受付時間、受付担当者、受付日時

倉庫未受付の再通知間隔と管理者エスカレーション時間は未確定。

## 14. 配送先と顧客直送

- 1注文1配送先。
- 自店舗、本部、支店、他店舗、顧客直送に対応する。
- 商品ごとに異なる配送先を指定するUIを作らない。
- 配送時間は指定なし／午前／午後。
- 午前・午後は到着保証ではない旨への同意を必須にする。
- 離島・配送困難地域でも注意・同意を表示する。
- 顧客直送は取扱店名義、納品書同梱、取扱店購入価格を顧客向け書類へ表示しない。
- 顧客向け納品書に価格を一切表示しないか、取扱店販売価格を表示するかは未確定。
- 自店舗、本部、支店、他店舗の配送先マスタを既存店舗設定と発注設定のどちらで管理するかは未確定。
- 顧客直送先を既存顧客マスタから選ぶか、注文ごとに手入力するかは未確定。

## 15. 在庫、入荷予定、GYEON本社PDF

- 正式在庫、予約・引当、入荷確認済み・棚卸待ち、バックオーダー、発注可能数量を厳密に分離する。
- 正式在庫が0でも、商品がバックオーダー可能なら発注できる。
- 入荷確認済み・棚卸待ち数量を正式在庫と表示しない。
- GYEON本社からの分納はなし。GYEON注文番号単位で一括入荷する。
- PDF解析結果は候補であり、自動確定しない。
- 必須注意文: 「PDF解析結果は候補です。担当者確認後に確定してください。」

## 16. 初回登録条件・アップグレード条件

- 新規Shop: 初回注文1回で、対象ケミカルの値引き前税別定価合計100,000円以上。
- 新規Detailer: Shop条件に加え、ONE EVO、PURE EVO、MOHS EVO、SYNCRO EVO、PRIMER、PREPを容量不問で各1点以上。
- 必須6商品と任意MATTは100,000円計算へ算入しない。
- MATTは任意。
- ShopからDetailerへのアップグレードでは100,000円条件を再要求せず、発送済み・未返品履歴から必須6商品の不足分を表示する。
- 条件未達時は最終発注ボタンを無効化し、達成金額、不足金額、不足商品、未達理由を表示する。
- 正式な資格達成は発送完了時。キャンセル、決済失敗、発送前取消は達成扱いにしない。

## 17. 販促グッズ

- 販促グッズと有償店舗用品を別カテゴリにする。
- 販促グッズだけの注文を禁止し、通常商品との同梱を必須にする。
- 販促グッズ金額は送料無料判定へ算入しない。
- のぼりは3種類、各種類1枚まで、3種類同時選択可。
- 実際の発送日から365日後に同じ種類を再申込可能とし、次回申込可能日を表示する。
