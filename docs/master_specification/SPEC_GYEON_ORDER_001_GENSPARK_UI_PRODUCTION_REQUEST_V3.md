## 1. 制作目的

GYEON取扱店が、商品検索、在庫確認、カート、オーナー承認、支払条件確認、バックオーダー方針、発送追跡、月次請求書確認を行う業務用発注UIを制作してください。

一般消費者向けECではありません。既存GYEON Detailer Agentの固定サイドバー、長方形ロゴ、濃紺系の配色、カード、文字、アイコンの世界観を維持してください。勝手な再設計は禁止します。

## 2. 仕様の優先順位

1. `SPEC_GYEON_ORDER_001_DEALER_ORDER_FORMAL_DECISION_V3.md`
2. 本制作依頼書
3. 既存の正式GYEON DA UI
4. 古いV2モックおよび参考画像

不一致がある場合はV3正式決定仕様を優先してください。不明点は質問として返し、デザインへ推測実装しないでください。

## 3. 絶対禁止

- DBテーブル、カラム、API、Webhook、role code、決済事業者の挙動を作らない。
- 未確定事項を確定画面にしない。
- スタッフへ最終発注権限を与えない。
- 掛け売り店舗へ支払方法選択を表示しない。
- 税別30,000円の送料無料判定を税込へ変えない。
- バックオーダーを注文全体statusへ追加しない。
- 土曜日を固定休業日にしない。
- 商品をケース単位へ丸めない。
- 商品ごとの配送先、商品ごとのバックオーダー発送方針を作らない。
- 配送先、顧客直送先、担当者、通知先、お気に入り、保存カートのデータ正本や新規CRUD権限を推測で確定しない。
- 既存DAのロゴ、サイドバー、ナビゲーションの世界観を変更しない。

## 4. 端末別レイアウト

### PC

- 左または中央に商品一覧。
- 右側に追従型カート。
- カテゴリと絞り込みを常時操作可能。

### Tablet

- 商品一覧を主領域。
- カートは折りたたみサイドパネル。
- PC機能を削除しない。

### Mobile

- 商品は一列。
- カテゴリ・絞り込みはドロワー。
- 下部固定カートバー。
- カートはボトムシート。
- 金額、在庫、発送予定、エラー理由を省略しない。

## 6. 主要フロー

### 6.1 スタッフ発注

```text
商品選択 → カート → 配送・支払条件入力 → オーナー確認依頼
→ オーナーが確認・修正 → 最終発注
```

スタッフ画面の主要ボタンは「オーナー確認を依頼」。最終発注ボタンは表示しないか権限拒否状態を明示してください。

### 6.2 通常店舗

```text
オーナー確認 → カード／銀行振込・前払い／代引きを選択
→ 支払方式別の注意事項へ同意 → 最終発注
```

### 6.3 掛け売り店舗

```text
オーナー確認 → 掛け売り条件を読み取り専用表示
→ 最終発注 → 倉庫作業キュー
```

支払方法選択UIを表示しないでください。

### 6.4 倉庫

```text
新規受注タスク → 倉庫受付確定 → ピック → 検品
→ 送り状確認 → 発送完了 → 取扱店通知
```

ベル通知だけではなく、消えない作業キューを主画面にしてください。

## 7. 支払方法カードの文言

### カード決済

> 営業日の当日締切時刻までに注文確定とカード承認が完了した在庫商品は、原則として当日発送します。休業日、締切後、在庫切れ、バックオーダー、承認遅延、住所確認が必要な場合は翌営業日以降となります。当日発送は当日到着を意味しません。

### 銀行振込・前払い

> ご入金確認後に発送します。振込名義が注文者名と異なる場合は、入金確認に時間がかかることがあります。振込手数料はお客様のご負担となります。

### 代金引換

> 営業日の当日締切時刻までに確定した在庫商品は、原則として当日発送します。顧客直送では選択できません。

バックオーダーを含む代引き注文では次を追加表示してください。

> 在庫商品を先に発送する場合、バックオーダー商品を含む注文金額の全額を最初のお届け時にお支払いいただきます。後日発送する商品について、代金引換による再請求はありません。

確認画面に「上記の発送条件を確認しました」の同意チェックを設けてください。

## 8. 倉庫営業カレンダー

カレンダーでは日ごとに通常営業、休業、臨時営業、短縮営業、締切時刻、理由を登録できるUIを制作してください。土曜日も営業日に設定できる必要があります。

発注画面の表示例:

> 最短発送可能日：2026年8月29日（土）<br>
> 本日の締切時刻までに注文が確定した場合の予定です。

休業日の表示例:

> 本日は倉庫休業日です。最短発送可能日は2026年8月31日（月）です。

「最短発送可能日」と「発送確定日」を別のラベル・状態で表現してください。

## 9. 掛け売り設定

スーパーアドミン画面で次を表現してください。

- 掛け売り有効／停止
- 月末締め（固定表示）
- 支払サイト
- 支払日
- 適用開始日
- 設定者・設定日時・変更履歴

掛け売り上限と支払遅延時の自動停止は未確定のため、正式入力項目として固定しないでください。提案する場合は別紙に分離してください。

取扱店側の確認表示例:

> お支払い：掛け売り<br>
> 締め日：毎月末日<br>
> 支払期限：翌月○日<br>
> この注文は月末締めの請求書にまとめて請求されます。

## 10. バックオーダー

バックオーダー商品を含む注文だけ、次の2択を表示してください。

- 在庫商品を先に発送
- すべて揃ってからまとめて発送

注文全体で一つだけ選びます。商品行ごとの選択は作らないでください。後日のバックオーダー発送に追加送料が発生しないことを表示してください。

## 11. 送料無料と初回条件

- 送料無料は値引き前の税別定価合計30,000円を初期基準とする。
- 販促グッズ、税、送料は算入しない。
- スーパーアドミン画面にはルール版、適用開始日時、変更履歴を表示する。
- 初回Shop／Detailer／アップグレード条件は正式決定仕様V3 §16をそのまま画面化する。
- 条件未達時は最終発注ボタンをdisabledにし、理由と不足内容を表示する。

## 12. PDFと通知

### PDF

- 注文履歴から発行済み納品書・請求書PDFを確認、ダウンロード。
- 未発行、作成中、発行失敗、権限なしを設計。
- GYEON本社PDF解析画面には「PDF解析結果は候補です。担当者確認後に確定してください。」を必須表示。

### 通知

ベルとお知らせ一覧で、オーナー確認依頼、注文受付、入金確認、入金確認保留、倉庫受付、発送準備、発送完了、発送予定変更、再与信失敗、請求書発行、支払期限、入金確認を表現してください。

倉庫側はベルだけにせず、新規受注・未受付・作業中・例外のタスクキューを設計してください。

### 既存システムとの連携が未確定の項目

配送先マスタ、顧客直送先、注文担当者、通知先、お気に入り、保存カートは、正式決定仕様V3 §20でデータ正本が未確定です。画面上は必要な選択・状態・説明を表現して構いませんが、「どの既存画面で登録するか」「新規登録できるか」「どのデータと共用するか」を正式仕様として固定しないでください。仮定はクリック可能プロトタイプの注記と未確定事項一覧へ分離してください。

## 13. 必須状態デザイン

- 通常、読込中、空、入力エラー、通信失敗、権限なし
- スタッフ下書き、オーナー確認待ち、差戻し、承認済み
- 在庫・価格・送料未設定、情報が古い
- 初回条件未達、販促グッズ単独注文拒否
- 入金待ち、入金確認保留、カード承認失敗、再与信失敗
- 倉庫営業日、休業日、締切前、締切後、発送予定変更
- 掛け売り有効、停止、請求書未発行、支払期限超過
- 倉庫未受付、受付済み、ピック中、検品エラー、送り状不一致、発送完了
- PDF未発行、作成中、失敗、解析未確認
