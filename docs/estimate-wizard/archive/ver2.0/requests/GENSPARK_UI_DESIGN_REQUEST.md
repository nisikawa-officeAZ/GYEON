# GenSpark UI Design Request — DealerOS Estimate Wizard
> **Scope**: UI/visual design ONLY. No workflow changes, no logic changes, no feature removal.
> **Source of truth**: Approved Estimate Wizard specification (`CURRENT_TASK.md`) + existing `EstimateEditor.tsx` behavior + v17 dashboard visual language.
> **Product language**: Japanese (ja). All labels below are the exact operator-facing strings; do not rename them.

### Architect 承認時の追加事項（binding・最優先）
1. **予約ルートをハードコードしない。** 常に「既存の予約ルート」を使用する（遷移先は将来変更されうる）。GenSpark は「既存の予約画面へ遷移する（動的解決）」前提でボタンをデザインすること。特定URLを画面に固定表記しない。
2. **納品は Desktop / Tablet / Smartphone の3種。** **ダークモードのみ**（ライトモードは不要・作成しない）。
3. **ワークフローを再設計しない。** ワークフローは承認済み。**変更してよいのは見た目のみ。画面とボタンの論理的な順序は不変。**

## 0. GenSpark への依頼概要（Brief）

DealerOS（全国 GYEON ディーラー向けマルチテナント SaaS）の **見積作成/編集画面** を、現在の「1画面スクロール型フルページエディタ」から **7ステップ・ウィザードUI** に再デザインしてください。

**目的**: 現場（detailing）の**業務効率化**と**スクロール削減**。既存の全機能・全入力項目・業務フローはそのまま保持します。

### 絶対厳守（binding constraints）
1. **既存ワークフローを発明・変更しない。** 下記の各ステップ・各項目は既存実装に1:1で対応します。順序・項目・操作を勝手に足し引きしない。
2. **業務ロジックを簡略化しない。** 価格計算・OCR・保存はエンジニア側で温存します。UIはその入出力面のみを描く。
3. **機能をひとつも削除しない。** 本書に列挙した入力/ボタン/セクションはすべて画面に存在させる。
4. **operator muscle memory を保持する。** ラベル・順序・コントロールの相対位置を現行踏襲。
5. **committing 操作を増やさない。** 遷移ボタン等で「保存までのクリック数」を増やす設計は不可（詳細は §14）。
6. **視覚デザインと現場効率が衝突したら、常に現場効率を優先。**

### 成果物（Deliverables）
GenSpark は以下を **自己完結型HTML（インラインCSS）＋スクリーンショット** で納品してください（実ファイル差し替え運用のため。React/実装コードは不要）:
- Desktop / Tablet / Smartphone 各ブレークポイントのウィザードシェル
- Step 1〜7 の全画面（各ブレークポイント）
- 常設合計パネル（Sticky Total）
- ステッパー、Back/Next/保存/PDF/LINE/カレンダー等の各ボタン状態（default / hover / active / disabled / loading）
- OCRアップロード＆レビューのオーバーレイ、LINE QR オーバーレイ
- アイコン/イラスト一式（§16）

## 1. Overall Design Philosophy（全体デザイン哲学）

- **プロフェッショナルな業務ツール**。ダーク基調（現行アプリ・v17 と統一）。装飾より情報密度と操作速度。
- **1ステップ＝1関心事**。各画面は「顧客」「車両」…の単一タスクに集中させ、縦スクロールを最小化。
- **金額は常時可視**（§13 Sticky Total）。現場は常に合計を見ながら作業する。
- **現場導線に忠実**: 受付→車両（車検証OCR）→サービス選択→明細調整→値引き→備考→確認/保存。
- **タッチ最優先**: タブレット/スマホでの現場入力を想定。48×48px 以上のタップ領域、iOSズーム防止のため入力は `text-base`（16px）相当。
- **状態が読み取れる**: 各ステップの完了/未完了/現在地がステッパーで一目で分かる。

---

## 2. Wizard Shell（ウィザード外枠）

共通シェルは全ステップで不変の骨格を提供する:

- **ヘッダー**: 画面タイトル（新規: 「見積作成」／編集: 「見積編集 #<見積番号>」）、閉じる/一覧へ戻る導線。
- **ステッパー（7ステップ）**: `1 顧客 / 2 車両 / 3 サービス / 4 明細 / 5 値引き / 6 備考 / 7 確認`。
  - 各ステップ: 番号 + ラベル + 状態（現在 / 完了 / 未着手 / 任意ジャンプ可）。
  - **全ステップへ1タップで自由ジャンプ可能**（§14）。
- **コンテンツ領域**: アクティブなステップの画面を表示。
- **常設合計パネル**（§13）: デスクトップは右サイド固定、タブレット/スマホは下部固定バー。
- **フッター/アクション**: Back / Next（前進ゲート・任意）、および最終ステップの主要アクション。
- **エラー/通知帯**: 保存失敗・バリデーション時の赤帯（現行 `text-red-400` 系）。

---

## 3. Desktop Layout（≥1024px）

- 最大幅 `max-w-6xl` 程度の中央寄せコンテンツ。
- **2カラム**: 左＝アクティブステップの入力領域（広い）／右＝**Sticky Total パネル＋主要アクション**（追従）。
- 上部に横型ステッパー（7ノードを水平配置）。
- パネルは角丸カード（`#1e293b`、`rounded-xl`、`shadow-lg`、内側 `p-5`）。
- セクション見出しは小型・大文字トラッキング（`text-slate-400 uppercase tracking-wider`）。
- 余白広め。モーダルの入れ子は禁止（OCR/QRは専用オーバーレイ）。

---

## 4. Tablet Layout（768–1023px）

- 単カラム主体、必要に応じ2カラム（例: 明細テーブル + 合計）。
- ステッパーは横型だがラベル短縮 or アイコン+番号中心に圧縮。
- Sticky Total は**下部固定バー**（合計 + 主要CTA）。
- タップ領域 48×48px、入力 `text-base`。

---

## 5. Smartphone Layout（<768px）

- **完全単カラム**、上から下へ1ステップ分のみ表示。
- ステッパーは**コンパクト**（例: 「3 / 7 サービス」表示 + ドット進捗、タップで一覧展開）。
- Sticky Total は**下部固定バー**（合計 + 主要CTA、1行圧縮）。
- OCR / LINE QR は**フルスクリーンに近い集中オーバーレイ**。
- 48×48px タップ、`text-base` 入力（iOSズーム防止）。

## 6. Step 1 — Customer（顧客）

現行の顧客セクションに1:1対応。**既存顧客選択**と**新規顧客作成**の両モードを保持:

- **モード切替チップ**: `既存顧客を選択` / `新規顧客を作成`（現行 `chip` スタイル、選択時 `bg-blue-950/40 border-[#1d4ed8]/60`）。
- **既存選択モード**: 顧客ドロップダウン（`顧客を選択...`）。
- **新規作成モード** — 全項目を保持（削除不可）:
  - 氏名、電話、メール、郵便番号、住所
  - **LINE ID** ＋ **LINE 友だち追加 QR**（QRはオーバーレイ表示）
  - **業者フラグ / 掛け率（％）**、**掛け売り可否（AR）**、**締め日 / 支払日**（法人請求フィールド）
  - 「この顧客を登録」ボタン（登録中は loading 表示）
- 登録後は選択済み顧客としてそのまま次工程へ（§14 auto-advance）。

---

## 7. Step 2 — Vehicle（車両）

現行の車両セクションに1:1対応。**既存車両選択**と**新規入力**の両モード + **車検証OCR** + **3M ボディサイズ推定**:

- **モード切替チップ**: `既存車両を選択` / `新規車両を入力`。
- **既存選択モード**: 車両ドロップダウン（選択顧客に紐づく車両でフィルタ）。車両が無い場合の案内文を保持。
- **車検証OCRボタン**: 押下で **OCRアップロード → レビュー** の2段オーバーレイ（§16）。既入力がある場合の上書き確認ダイアログ挙動を保持。
- **新規/編集の拡張フィールド**（すべて保持）:
  メーカー / 車名 / グレード / 型式（vehicle_code）/ 車台番号（VIN）/ 初度登録年月 / 登録年月日 / 車検満了日 / 排気量 / 色 / ナンバー
- **ボディサイズ（3M推定）**: サイズ区分 `SS / S / M / ML / L / LL / XL` の選択と、3M自動推定（`sizeEstimate`）の表示・再推定操作。サイズは Step 3 の価格計算に連動（表示上も明示）。
- 「保存時に車両として登録されます」の注記を保持。

---

## 8. Step 3 — Category / Service Selection（サービス｜明細生成）

**最大のスクロール源**。カテゴリ別に整理して縦積みを解消（例: 折りたたみ/タブ/アコーディオン）。**全サービス種別・全オプションを保持**。各カテゴリに「**明細に追加**」ボタン（現行 blue アウトライン: `text-blue-400 border-blue-500/30 bg-blue-500/5`）。

保持すべきカテゴリ（削除・簡略化不可）:
1. **コーティング**: コーティング選択（ディテーラーランク/Certified 制御による表示切替）、トップコート2層/3層、コーティングオプション（複数選択）。
2. **PPF（プラン）**: プラン、フィルム種別、車両ランク、フロントガラス有無。
3. **PPF（部位別・プラン非依存）**: 部位ごとの選択 / 価格編集 / 数量（一部部位は数量必須）。追加可否バリデーション表示を保持。
4. **ウィンドウフィルム**: 部位（複数）、グレード。
5. **メンテナンス**: メニュー複数選択。※**新規作成モード時のみ表示**（編集時は非表示）—この非対称を保持。
6. **洗車**: メニュー複数選択。※同上、**新規作成モード時のみ**。
7. **ルームクリーニング**: 部位（複数）、状態（condition）。
8. **その他**: 名称 + 価格の自由入力。

- 補助文言を保持: 「カテゴリを設定し『明細に追加』で価格表から明細を生成します。生成後は下の明細で数量・割引を調整できます。」
- 「明細に追加」は価格エンジンで明細行を生成（UIは結果表示のみ、計算はしない）。追加後は Step 4（明細）へ自然遷移可（§14）。

---

## 9. Step 4 — Estimate Editor（明細）

生成された明細行の編集テーブル。現行を保持:

- 列: 品目名 / 数量 / 単価 / 割引 / 小計。
- **数量・割引はインライン編集可**、行削除可、**「＋ 行を追加」で手入力行**を追加可。
- 空状態文言を保持: 「明細がありません。上のサービスから追加するか『＋ 行を追加』で手入力してください。」
- 金額列は `tabular-nums`（桁揃え）。
- モバイルはテーブル横スクロール（`overflow-x`）で対応、行を潰さない。

---

## 10. Step 5 — Discount / Coupon（値引き）

現行の割引UIを保持:

- **クーポン枠（複数）**: 既定「新規ご来店クーポン ¥5,000 / 紹介特典クーポン ¥5,000 / キャンペーンクーポン ¥10,000」等をトグル選択。
- **手動値引き（金額入力）**。
- **業者掛け率**: 業者フラグ ON 時に掛け率（％）による値引きを適用。
- 各値引きは合計へ即時反映（Sticky Total に連動表示）。

---

## 11. Step 6 — Notes（備考・メモ）

- **お客様向け備考**（見積書に記載）: textarea、プレースホルダ「見積書に記載する備考...」。
- **社内メモ**（見積書には出ない）: textarea、プレースホルダ「社内向けメモ（見積書には出ません）...」。OCR結果ブロックの追記先でもある。
- 2項目とも保持。

---

## 12. Step 7 — Review / Save（確認・保存）

最終確認と確定アクション。閲覧しやすいサマリ + 主要ボタン群:

- **サマリ表示**: 顧客 / 車両 / サービス概要 / 明細 / カテゴリ別小計 / 小計 / 値引き / 消費税（税率%）/ **合計**。
- **主要アクション**:
  - **保存**（新規: 見積作成／編集: 更新）。`catalog`（ディーラー価格表）ロード完了までは保存を保留（ロード中表示）。
  - **PDF表示**（既存PDF出力へ）。
  - **LINE**（既存LINE画面へ）。
  - **予約日を決めてカレンダー登録**:
    - 押下時に**まず見積を自動保存**し、その後**既存の予約画面へ遷移**。
    - **遷移先はハードコードしない**。常に「既存の予約ルート」を動的に使用する（遷移先URLは将来変更されうるため、画面上に特定URLを固定表記しない）。
    - （実装側の注記: 既存ルートあり＝有効ボタン。仮に遷移先が解決できない場合は `disabled` かつラベル「**予約機能は準備中です**」。GenSpark は**有効状態と無効状態の両方**をデザインしてください。）
- ボタン状態（default/hover/active/disabled/loading）を全て用意。

---

## 13. Sticky Total Panel（常設合計パネル）

- **全ステップで常時可視**（Step 7 だけに隠さない）。
- 表示内容: カテゴリ別小計（表示のみ）/ 小計 / 値引き / 消費税（税率%）/ **合計**（強調）。
- Desktop: 右カラム上部固定。Tablet/Smartphone: 下部固定バー（合計 + 主要CTA）。
- 価格未確定（カタログ読込中）の**ローディング状態**を用意。
- 金額は `tabular-nums`、合計は最も強いコントラスト（`text-white`）。

---

## 14. Navigation Behavior（ナビゲーション挙動）

- **自由ジャンプ**: ステッパーの任意ステップへ1タップで移動可（編集時に特に重要）。
- **Back / Next は補助**: Next は前進ゲートのみで**必須ブロックしない**（未入力でも進める）。確定検証は保存時に一括。
- **auto-advance（重要・operation-count 対策）**: 既存の committing 操作に前進を同居させ、**遷移専用のクリックを新設しない**:
  - 既存顧客を選択 → 車両へ自動前進
  - OCRレビュー確定 → 車両確定へ
  - 「明細に追加」 → 明細ステップへ自然遷移
- **committing 操作の定義（承認済み）**: 顧客/車両/サービス選択・データ入力・明細追加・値引き/クーポン適用・保存・PDF/LINE/カレンダー。**scroll・ステップ遷移・パネル開閉はカウントしない。**
- **未保存ガード**: ページ離脱（ブラウザバック/リロード/タブ閉じ/一覧遷移）時のみ確認。**ウィザード内のステップ移動では警告を出さない。**

---

## 15. Button Placement（ボタン配置）

- **Back**: 左下（または左）。**Next**: 右下（または右）。左右の相対位置は全ステップ固定（muscle memory）。
- **「明細に追加」**: 各サービスカテゴリのカード内・右寄せ（現行踏襲）。
- **主要CTA（保存）**: Desktopは右サイド合計パネル内、Tablet/Smartphoneは下部固定バー。
- **Step 7 のアクション群**（保存 / PDF / LINE / 予約カレンダー）は視覚的に階層化（保存＝プライマリ、他＝セカンダリ）。
- 破壊的操作（行削除等）は控えめだが誤タップ防止の配置。

---

## 16. Required Illustrations / Icons（必要なアイコン・イラスト）

- **ステップアイコン**（7種）: 顧客（人）/ 車両（車）/ サービス（スパークル or ツール）/ 明細（リスト）/ 値引き（タグ or %）/ 備考（メモ）/ 確認（チェック）。
- **アクションアイコン**: 保存 / PDF / LINE（公式LINE風グリーン系だがダークUIに調和）/ カレンダー（予約）/ 追加（＋）/ 削除（ゴミ箱）/ 編集。
- **OCR フロー**: 車検証アップロード（カメラ/書類）、スキャン中、レビュー（確認）アイコン。
- **LINE QR**: QRコード提示オーバーレイ用の枠デザイン。
- **状態アイコン**: 完了（チェック）/ 現在地 / エラー（警告 amber/red）/ ローディング（スピナー）。
- スタイル: 線画中心・ダーク背景で視認性の高いストローク。過度な装飾やフルカラーイラストは避ける。

## 18. Typography（タイポグラフィ）

- 既定 sans-serif（システムフォント、現行 Tailwind 既定）。日本語可読性優先。
- セクション見出し: `text-xs font-semibold uppercase tracking-wider text-slate-400`。
- ラベル: `text-xs font-medium text-slate-400`。
- 入力/本文: `text-base`（モバイル、iOSズーム防止）/ `sm:text-sm`（デスクトップ）。
- 明細・金額: 数字は `tabular-nums`（桁揃え）。合計は最大ウェイト/コントラスト。
- 密度の高いテーブルは `text-xs`〜`text-sm` を許容。

---

## 19. Spacing（余白・密度）

- カード内パディング `p-5` 基準（v17 密度に整合）。
- セクション間は視認可能な余白、ただし冗長な空白は避け**スクロール削減**を優先。
- フォーム項目は縦積み時 `gap` を一定に。ラベルと入力の間隔を統一。
- タッチ領域は最小 48×48px。
- 角丸 `rounded-lg`（入力/ボタン）/ `rounded-xl`（カード）で統一。

## 20. Responsive Behavior（レスポンシブ挙動 — v17 準拠）

- ブレークポイント: **Mobile `<768` / Tablet `768–1023` / Desktop `1024+`**（v17 準拠）。
- Desktop: 2カラム（入力 + Sticky Total 右追従）。
- Tablet: 単カラム + 下部固定合計バー、ステッパー圧縮。
- Mobile: 単カラム、コンパクトステッパー（「n / 7」+ ドット）、下部固定合計バー、OCR/QRはフルスクリーン級オーバーレイ。
- テーブル等の広い要素は各自 `overflow-x: auto` 内でスクロール（本文横スクロール禁止）。

## 21. Animation / Transition Behavior（アニメーション・トランジション）

- **控えめ・高速**（業務効率優先）。過度なモーションは不可。
- ステップ切替: 軽いフェード/スライド（150–200ms 程度）。連続入力を妨げない。
- 合計金額の更新: 数値変化を軽くハイライト（点滅は不可、色/背景の短いパルス程度）。
- ボタン: hover/active のトランジション（`transition-colors`）を現行踏襲。
- ローディング: スピナー or スケルトン（カタログ読込中・保存中・OCR処理中）。
- オーバーレイ（OCR/QR）: フェードイン + 軽いスケール。閉じるは即時。
- **アクセシビリティ**: `prefers-reduced-motion` 尊重。
