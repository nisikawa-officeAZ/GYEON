# A. 概要・目的

DealerOS（全国 GYEON ディーラー向けマルチテナント SaaS）の**見積作成/編集画面**を、現在の「1画面スクロール型フルページエディタ」から **7ステップ・ウィザードUI** に再デザインする。

- **目的**: 現場（detailing）の**業務効率化**と**スクロール削減**。
- 既存の**全機能・全入力項目・業務フロー・全文言をそのまま保持**する（見た目のみ変更）。
- **ダークモードのみ**（ライトモードは作らない）。
- **納品は Desktop / Tablet / Smartphone の3デバイス**。

### 納品物一覧
1. ウィザードシェル（3デバイス）
2. Step 1〜7 の全画面（7×3デバイス）
3. Sticky Total（合計）パネル（展開/折りたたみ/読込中の各状態）
4. 全ボタンの状態一覧（default / hover / active / disabled / loading）
5. OCR アップロード＆レビュー オーバーレイ、LINE QR オーバーレイ
6. アイコン一式（後述 §F-16）
7. **motion spec**（遷移仕様）ページ
8. **design tokens リファレンス**（配色/タイポ/余白トークン一覧）ページ

# B. 禁止事項（binding・最優先）

1. **既存ワークフローを発明・変更しない。** 画面とボタンの**論理的な順序は不変**。
2. **業務ロジックを簡略化しない。** 価格計算・OCR・保存はエンジニア側で温存。UIは入出力面のみ描く。
3. **機能をひとつも削除しない。** 本書 §E に列挙した入力/ボタン/セクションはすべて画面に存在させる。
4. **operator muscle memory を保持する。** ラベル・順序・コントロールの相対位置を現行踏襲。
5. **committing 操作を増やさない。** 「保存までのクリック数」を増やす設計は不可（§C-定義参照）。遷移ボタン・確認ダイアログの追加で操作を増やさない。
6. **視覚デザインと現場効率が衝突したら、常に現場効率を優先。**
7. **予約ルートをハードコードしない。** 常に「既存の予約ルート」を動的使用（遷移先は将来変更されうる）。特定URLを画面に固定表記しない。
8. **新色を発明しない。** §F-17 のトークン範囲でデザインする。
9. **文言を変えない・翻訳しない。** §E の実文言をそのまま使用。
10. **【最重要・UI3移行】プルダウン（ドロップダウン / `select`）を全面禁止。** すべての選択は**押しボタン式**（chip / セグメント / 選択カード / タップ選択リスト）でデザインし、**何が選択されているかを開かずに一目で把握できる**ようにする。ネイティブ `select`・折りたたみで隠れる選択UIは使わない。詳細は §D-選択コントロール規則 と §E の注記を参照。

# C. ワークフロー（承認済み・不変）

## ステップ構成（7ステップ＝現場受付導線順）
`1 顧客 → 2 車両 → 3 サービス → 4 明細 → 5 値引き → 6 備考 → 7 確認/保存`

各ステップは既存 `EstimateEditor` の各セクションに **1:1 対応**（統合・分割・並べ替え禁止）。

## ナビゲーション挙動
- **自由ジャンプ**: ステッパーの任意ステップへ1タップで移動可（新規・編集とも／編集で特に重要）。
- **Back / Next は補助**: Next は前進ゲートのみで**必須ブロックしない**（未入力でも進める）。**確定検証は保存時に一括**。
- **auto-advance**（重要・operation-count 対策）: 既存の committing 操作に前進を同居させ、**遷移専用のクリックを新設しない**:
  - 既存顧客を選択 → 車両へ自動前進
  - OCRレビュー確定 → 車両確定へ
  - 「明細に追加」 → 明細ステップへ自然遷移
  - **可視化**: 自動前進時は **1〜1.5秒の軽いトースト**（例「車両ステップへ移動しました」）。確認スナックバー等の追加操作は不可。
- **未保存ガード**: ページ離脱（ブラウザバック/リロード/タブ閉じ/一覧遷移）時のみ確認。**ウィザード内のステップ移動では警告を出さない。**

## committing 操作の定義（承認済み）
**数える**: 顧客/車両/サービス選択・データ入力・明細追加・値引き/クーポン適用・保存・PDF/LINE/カレンダー。
**数えない**: スクロール・ステップ遷移・ウィザードページ間移動・パネル/ステップの開閉。

# D. UIデザイン依頼

## §F-1. 全体デザイン哲学
- **プロフェッショナルな業務ツール**。ダーク基調。装飾より情報密度と操作速度。
- **1ステップ＝1関心事**。縦スクロールを最小化。
- **金額は常時可視**（Sticky Total）。現場は常に合計を見ながら作業する。
- **タッチ最優先**: 48×48px 以上のタップ領域、iOSズーム防止のため入力は `text-base`（16px）相当。
- **状態が読み取れる**: 完了/現在地/未着手がステッパーで一目で分かる。

## §F-1b. 選択コントロール規則（UI3移行・binding・最重要）
- **プルダウン（`select` / ドロップダウン）を一切使わない。** 全選択は**押しボタン式**で、選択状態が常時可視であること。
- **少数の列挙選択肢**（コーティング・トップコート・PPFプラン/フィルム/ランク/フロントガラス・ウィンドウグレード・ルーム状態・ボディサイズ 等）→ **chip / セグメントボタン / 選択カード**。選択中は塗り＋境界で明示（`bg-blue-950/40 border-[#1d4ed8]/60`）、非選択は `border-slate-700`。
- **多数の動的レコード**（顧客・車両）→ **タップ選択式のリスト/カード**（必要に応じ検索・絞り込みボックス付き）。選択済みは強調表示。**ネイティブのプルダウンにしない。**
- 「〜を選択...」というプレースホルダ的空 option は不要（押しボタン群で未選択状態を表現）。
- 直感性優先：**開く操作なしに現在の選択が読み取れる**こと。committing 操作は増やさない（タップ選択は既存の選択操作と同数）。

## §F-2. ウィザードシェル
- **ヘッダー**: タイトル（新規「新規見積」／編集「見積編集」＋見積番号）、一覧へ戻る導線。
- **ステッパー（7）**: `1 顧客 / 2 車両 / 3 サービス / 4 明細 / 5 値引き / 6 備考 / 7 確認`。
  - **全ステップ常時クリック可・均等表示**（新規/編集で見た目を変えない）。完了ステップに**控えめなチェック**のみ付与。**未到達ステップをロック/減光しない**。
- **コンテンツ領域**: アクティブなステップのみ表示。
- **常設合計パネル**（§F-13）: Desktop 右サイド固定、Tablet/Smartphone 下部固定バー。
- **フッター/アクション**: Back / Next（補助）、最終ステップの主要アクション。
- **エラー/通知帯**: 赤帯（`border-red-500/30 bg-red-500/10 text-red-400`）。

## §F-3〜5. レスポンシブ（→ §G に詳細）

## §F-13. Sticky Total（常設合計）パネル
- **全ステップで常時可視**（Step7 だけに隠さない）。
- 内訳: カテゴリ別小計（表示のみ）/ 小計 / 値引き / 消費税（税率%）/ **合計**（`text-white` 強調）。
- **展開度**: **Desktop は常時展開／モバイル（Tablet・Smartphone）は「合計のみ + タップで内訳シート」**（下部バーの圧迫回避）。
- カタログ読込中の**ローディング状態**を用意。金額は `tabular-nums`。

## §F-14. ナビゲーション挙動 → §C 参照。

## §F-15. ボタン配置
- **Back**: 左（下）。**Next**: 右（下）。左右の相対位置は全ステップ固定。
- **「明細に追加」**: 各サービスカテゴリのカード内・右寄せ。
- **主要CTA（保存）**: Desktop は右サイド合計パネル内、Tablet/Smartphone は下部固定バー。
- **Step7 のアクション群**（保存 / PDF / LINE / 予約カレンダー）は視覚階層化（保存＝プライマリ、他＝セカンダリ）。
- 破壊的操作（行削除等）は控えめ配置。**確認ダイアログは追加しない**（誤タップ対策は間隔・配置・「元に戻す」トーストで）。

## §F-16. 必要なアイコン・イラスト
- **ステップアイコン7種**: 顧客（人）/ 車両（車）/ サービス（スパークル or ツール）/ 明細（リスト）/ 値引き（タグ or %）/ 備考（メモ）/ 確認（チェック）。
- **アクション**: 保存 / PDF / LINE（グリーン系だがダークUIに調和）/ カレンダー（予約）/ 追加（＋）/ 削除（ゴミ箱）/ 編集。
- **OCRフロー**: 車検証アップロード（カメラ/書類）、スキャン中、レビュー（確認）。
- **LINE QR**: QR提示オーバーレイの枠。
- **状態**: 完了（チェック）/ 現在地 / エラー（amber/red）/ ローディング（スピナー）。
- スタイル: **線画中心・ダーク背景で視認性の高いストローク**。過度な装飾・フルカラーイラストは避ける。
- **空状態**: テキスト＋小さな線画アイコンのみ（装飾ゼロ）。

## §F-18. タイポグラフィ
- 既定 sans-serif（日本語可読性優先）。
- 見出し `text-xs font-semibold uppercase tracking-wider text-slate-400`。ラベル `text-xs font-medium text-slate-400`。
- 入力/本文 `text-base`（モバイル・iOSズーム防止）/ `sm:text-sm`（デスクトップ）。
- 金額は `tabular-nums`、合計は最大ウェイト/コントラスト。密なテーブルは `text-xs`〜`text-sm`。

## §F-19. 余白・密度
- カード内 `p-5` 基準。セクション間は視認可能な余白、ただし冗長な空白は避け**スクロール削減**優先。
- タップ領域最小 48×48px。角丸 `rounded-lg`（入力/ボタン）/ `rounded-xl`（カード）。

## §F-21. アニメーション・トランジション（motion spec）
- **控えめ・高速**（業務効率優先）。過度なモーション不可。
- ステップ切替: 軽いフェード/スライド（150–200ms）。
- 合計金額更新: 短い色/背景パルス（点滅不可）。
- ボタン: `transition-colors`。ローディング: スピナー or スケルトン（カタログ読込中・保存中・OCR処理中）。
- オーバーレイ（OCR/QR）: フェードイン＋軽いスケール、閉じるは即時。
- `prefers-reduced-motion` を尊重。

- **上書き確認は別小型モーダル**:「入力済みの車両情報があります。OCR結果で上書きしますか？（キャンセル＝空欄のみ補完）」

## 定数
- CATEGORY_LABEL: `coating→コーティング / ppf→PPF / window→ウィンドウ / interior→インテリア / glass→ガラス / other→その他 / maintenance→メンテナンス / carwash→洗車 / roomclean→ルームクリーニング`

- ボディサイズ既定: `SS / S / M / ML / L / LL / XL`

## 保持必須の挙動（機能欠落防止）
1. ウィンドウ/ルームクリーニングは**単一インスタンス**（再追加で重複せず更新）。
2. メンテナンス/洗車は**新規作成時のみ表示**（編集時は非表示・既存明細行は明細テーブルに残る）。
3. 明細行削除は**確認なし即時**（確認ダイアログを足さない／誤タップ対策は undo トースト）。
4. 「保存」は `catalogReady` 完了まで disabled。
5. PDF/LINE/予約は保存済み前提（予約は保存を自動実行してから遷移）。

# F. レスポンシブ（v17 準拠）

- ブレークポイント: **Mobile `<768` / Tablet `768–1023` / Desktop `1024+`**。
- 広い要素（明細テーブル等）は各自 `overflow-x: auto` 内でスクロール（本文の横スクロール禁止）。
- タップ 48×48px、入力 `text-base`。

---

# G. Desktop（≥1024px）

- 最大幅 `max-w-6xl` 程度の中央寄せ。
- **2カラム**: 左＝アクティブステップの入力領域（広い）／右＝**Sticky Total パネル＋主要アクション**（追従 sticky）。
- 上部に**横型ステッパー**（7ノード水平配置）。
- **Step3 レイアウト**: **左サイド縦タブ**（カテゴリ一覧を左、右に選択カテゴリ詳細）。カテゴリ切替＝スクロールでなくタブ選択でタスク切替コスト最小。
- Sticky Total は**常時展開**（カテゴリ別小計まで表示）。
- カードは `#1e293b`・`rounded-xl`・`shadow-lg`・`p-5`。モーダル入れ子禁止（OCR/QRは専用オーバーレイ）。

---

# H. Tablet（768–1023px）

- 単カラム主体（必要に応じ明細＋合計を2カラム）。
- ステッパーは横型だがラベル短縮 or アイコン+番号で圧縮。
- **Step3 レイアウト**: 縦タブ（Desktop 準拠）または上部横タブ。
- Sticky Total は**下部固定バー**（「合計のみ + タップで内訳シート」）。
- タップ 48×48px、入力 `text-base`。

---

# I. Smartphone（<768px）

- **完全単カラム**、1ステップ分のみ表示。
- ステッパーは**コンパクト**（例「3 / 7 サービス」+ ドット進捗）。**タップで展開＝ボトムシート**で全ステップ一覧（iOS標準的・片手操作）。
- **Step3 レイアウト**: **カテゴリカードのグリッド → タップで詳細展開**（タッチ最適）。カテゴリの順序・ラベル・全項目は Desktop と同一（muscle memory 維持）。
- Sticky Total は**下部固定バー**（合計のみ + タップで内訳シート）。
- OCR / LINE QR は**フルスクリーンに近い集中オーバーレイ**。
- 48×48px タップ、`text-base` 入力（iOSズーム防止）。
